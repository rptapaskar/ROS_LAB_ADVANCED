00 · THE OFFICIAL MISSION

What Experiment 01
is actually about.

The laboratory plan defines this as an introductory experiment: identify the robot's mechanical, electrical, sensing and computing subsystems; trace a command from software to physical wheel motion and back to measurement; become operationally independent on Linux; and follow the safety protocol.

🔍

Mission A — Decode the robot

Identify the drive train, wheel encoders, IMU, RPLIDAR, RealSense depth camera, robot controller, computing unit, battery and emergency stop.

💻

Mission B — Become Linux-ready

Use the terminal, filesystem, packages, processes, permissions and remote access over SSH without needing someone beside you.

🔁

Mission C — Trace the signal

Understand the loop: software command → controller → motors → wheels → physical motion → sensors → computer.

🛑

Mission D — Operate safely

Know the powered-robot operating protocol and the role of the emergency stop before you start moving hardware.

Golden rule: You are not learning commands to memorize commands. You are learning commands because a robotics engineer must be able to inspect, operate, diagnose and control a computing system that is attached to a physical machine.

02 · ENTER THE ROBOT'S COMPUTER

Linux is your
robotics cockpit.

The lab deliberately introduces the computing platform before ROS commands. If you cannot confidently navigate the machine, inspect files, understand running processes or connect remotely, debugging ROS later becomes painful.

📁

Filesystem

Linux organizes everything through a hierarchical filesystem. Your terminal lets you move through directories, inspect files and create your own workspace.

📦

Packages

Software is installed and managed through package-management tools. You should understand what a package is and how to inspect/install/remove software safely.

⚙️

Processes

Programs become processes. Robotics involves many processes running together, so you need to inspect what is running and understand how processes start/stop.

🔐

Permissions

Linux controls who can read, write or execute resources. Permissions matter when scripts, devices or files refuse to behave.

🌐

SSH

Secure Shell lets you operate the robot computer remotely from another machine on the network.

📤

File transfer

Once connected remotely, you may need to move scripts and data between your workstation and the robotics computer.

COMMAND EXPLAINER

pwd — Where am I?

pwd

Print Working Directory. It tells you the absolute path of the directory your shell is currently operating in. This is your first “orientation check” whenever you are unsure where you are.

Robotics habit: Before running a command that changes or deletes files, confirm your location with pwd.
pwd
Print working directoryCORE

Shows the full path of your current directory. Use it to orient yourself.

ls
List directory contentsCORE

Shows files and folders. Try ls -l for details and ls -la to include hidden entries.

cd
Change directoryCORE

Moves the shell to another directory. cd .. moves one level up; cd ~ returns to your home directory.

mkdir
Make directoryCORE

Creates a folder. Example: mkdir robot_test.

touch
Create an empty file / update timestampCORE

Useful for creating a placeholder file such as touch notes.txt.

cp
CopyCORE

Copies files or directories. Example: cp config.yaml backup.yaml.

mv
Move / renameCORE

Moves a file or changes its name. Example: mv old.txt new.txt.

rm
RemoveCAUTION

Deletes files. There is usually no recycle bin in the shell. Treat rm as a deliberate action.

cat
Print file contentsCORE

Quickly displays a small text file. For large files use less.

less
Read a file interactivelyCORE

Scroll through a file without loading the entire thing into your mental RAM. Press q to quit.

head / tail
View beginning / end

Useful for checking logs. Example: tail -f robot.log follows a growing log file.

grep
Search text

Find matching text inside output/files. Example: grep ERROR robot.log.

find
Find files/directories

Search by name or other properties. Example: find . -name "*.py".

file
Identify file type

Reports what a file actually is based on its contents.

df -h
Disk space

Shows filesystem disk usage in human-readable units. Useful when logs/data fill the robot computer.

du -sh
Directory size

Shows how much space a directory consumes.

whoami
Current userCORE

Tells you which user account the shell is using. Important when permissions behave unexpectedly.

hostname
Machine name

Shows the system's host name, useful when working with multiple computers.

uname -a
System/kernel information

Displays Linux kernel and system information.

ps
Process snapshotCORE

Shows running processes. ps aux is a common broader view.

top
Live process monitorCORE

Displays active processes and resource usage. Press q to exit.

kill
Send signal to processCAUTION

Stops/controls a process by PID depending on the signal. Never kill an unknown robotics process blindly.

chmod
Change permissionsCORE

Changes read/write/execute permissions. Example: chmod +x script.sh makes a script executable.

sudo
Run with elevated privilegesCAUTION

Executes a command with administrative privileges when permitted. Use only when required and when you understand the command.

apt
Package managementCORE

On Debian/Ubuntu systems, apt can search, install, update and remove software packages. Follow your lab's approved package procedure.

ssh
Remote loginCORE

Securely opens a remote shell. Typical form: ssh username@robot-host.

scp
Secure file copyCORE

Copies files over SSH. Example: scp notes.txt username@robot-host:~/.

exit
Leave shell / SSH sessionCORE

Ends the current shell session. In SSH, it returns you to your local computer.

Important: Exact package names, usernames, hostnames, IP addresses, robot paths and administrative commands are platform-specific. Your instructor/lab machine configuration is authoritative. Do not invent or guess them.
04 · SSH — REMOTE PILOT MODE

Your laptop.
The robot's computer.
One terminal.

🔐

What SSH does

SSH creates an encrypted remote shell session. You type commands on your machine; they execute on the remote robotics computer.

ssh username@robot-host
📦

What SCP does

SCP transfers files through the SSH mechanism. It is useful for moving scripts, configuration files or collected data.

scp file.txt username@robot-host:~/

05 · SAFETY IS A TECHNICAL SKILL

Before “RUN”.
Think “SAFE”.

The experiment explicitly requires students to apply the laboratory safety and operating protocol when working with a powered mobile robot.

🛑 Never improvise

  • Do not power or move the robot without following the laboratory procedure.
  • Know where the emergency stop is before enabling motion.
  • Keep people, cables and objects clear of the robot's path.
  • Do not run an unfamiliar command just because it appears online.
  • Do not use sudo, rm or process-killing commands casually.

✅ Engineer the session

  • Inspect the robot and its surroundings before operation.
  • Confirm your terminal is connected to the intended machine.
  • Understand what a command will change before executing it.
  • Start with controlled, low-risk checks before physical motion.
  • If something behaves unexpectedly: stop, make the system safe, then diagnose.
06 · WORLD VS ROBOT

Not every sensor
answers the same question.

One of the key learning outcomes is being able to distinguish measurements of the world from measurements of the robot itself — and explain why that distinction matters.

🌍

“What is happening outside me?”

RPLIDAR observes surrounding geometry. RealSense provides depth information about the environment. These are exteroceptive/environment-facing measurements.

🧍

“What is happening to me?”

Wheel encoders measure wheel rotation. IMU measures inertial quantities. These are proprioceptive measurements about the robot's own motion/state.

Why it matters: Later in the course you will combine imperfect measurements. You need to understand what each sensor actually observes before you can decide how it should influence estimation or navigation.
