Core idea: a depth image is not “just another camera picture.” Each valid pixel can represent a measured distance — but only if you correctly understand its encoding, units, geometry and validity.
01 · WHAT IS DEPTH?

RGB says what.
Depth says how far.

An RGB image describes appearance using colour channels. A depth image adds geometric information: each pixel corresponds to a measured distance along the camera's sensing geometry, subject to the camera's operating range and validity rules.

SCENEReal 3D objects.
SENSEStereo / structured light.
ENCODEDepth pixels.
DECODEUnits + validity.
INTERPRETROI distance.

📏

Depth value

Z = decoded depth value

The numerical pixel value must be interpreted using the image encoding and unit convention provided by the camera/ROS interface.

🚫

Invalid depth

invalid ≠ “very far”

Invalid or unavailable depth should be handled explicitly. Never silently treat missing data as a safe obstacle distance.

Important: the exact depth encoding, unit scale and invalid-value convention depend on the camera driver/message. Inspect the actual message metadata rather than assuming a datatype or unit.

03 · REGION OF INTEREST

Don't ask one pixel.
Ask the neighbourhood.

Real depth images contain missing pixels, edge effects and local noise. A region of interest (ROI) lets you collect multiple measurements from the area where an obstacle is expected and derive a robust nearest-obstacle distance.

DEPTH IMAGE · ROI PROCESSING
ROBUST DISTANCE → 0.84 m

🎯 ROI workflow

Choose an image region that is meaningful for the robot's safety/control problem. Then:

  • Extract depth values inside the ROI.
  • Discard invalid pixels.
  • Apply the defined range/validity constraints.
  • Use a robust statistic to estimate the nearest obstacle distance.
  • Publish the resulting distance for the controller.
Why robust? One bad pixel should not cause a false emergency stop — but the algorithm should still remain sensitive to a genuine nearby obstacle. Your chosen statistic and filtering policy should be documented.
🎯

ROI

R = {Z(u,v) | (u,v) ∈ ROI}

The ROI is a set of image pixels selected for the obstacle-distance calculation.

📊

Robust estimate

dobs = robust(Rvalid)

Use the laboratory's chosen robust estimator; the key is to remove invalid measurements before estimating distance.

04 · DEPTH → 3D GEOMETRY

A pixel is 2D.
The obstacle is 3D.

Camera intrinsics connect image coordinates to the camera's geometry. When required, a valid depth value can be deprojected from pixel coordinates into a 3D point in the camera coordinate system.

📐

Pinhole relationship

x = (u − cx) Z / fx

Horizontal image coordinate u maps to camera-coordinate x using focal length and principal point.

📐

Vertical relationship

y = (v − cy) Z / fy

Vertical image coordinate v maps to camera-coordinate y using the corresponding intrinsic parameters.

📏

Depth axis

Z = depth(u,v)

The exact interpretation of Z must match the camera's depth convention and the operation being performed.

🎯

Why intrinsics matter

pixel → ray → 3D point

Without the correct camera model, image coordinates cannot be reliably related to physical geometry.

Pre-lab connection: you were asked to review deprojection using camera intrinsics. You do not need to deproject every pixel to perform a simple distance ROI, but understanding the geometry explains why pixel location, focal length and depth belong together.

Mean reported distance: where the sensor estimate sits on average.

11 · COMMON FAILURE MODES

When depth looks weird,
investigate.

⬛ Missing depth

A region contains too many invalid pixels to produce a reliable distance.

Check target material, illumination, operating range, ROI placement and validity handling.

✨ Reflective target

Glass or specular surfaces can produce unstable or unavailable depth.

Relate the failure to how the depth sensing method obtains usable returns/correspondences.

🌑 Dark target

A dark surface may produce reduced depth availability under some sensing conditions.

Compare valid-pixel fraction and error rather than relying on a single visual impression.

📐 Wrong geometry

Depth values are numerically plausible but interpreted with the wrong frame/intrinsics.

Inspect camera info and TF relationships before changing the algorithm.

🔢 Wrong units

The controller threshold is off by a scale factor.

Inspect the actual image encoding and unit convention before touching the threshold.

🎯 Bad ROI

The ROI includes background, floor or irrelevant pixels and produces a misleading obstacle estimate.

Visualise and justify the ROI relative to the robot's safety/control objective.
